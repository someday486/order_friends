# 2026-04-08 패치 노트

## 개선 사항
- `/shop` 첫 진입 시 공개 브랜드 목록을 서버에서 먼저 렌더링하도록 바꿔, 브랜드 선택 전 스켈레톤만 오래 보이던 대기 시간을 줄였습니다.
- 서버 측 API 베이스를 사용할 수 없는 환경에서는 기존 클라이언트 `/public/brands` 요청으로 자동 폴백되도록 유지했습니다.
- `develop` 브랜치의 변경 사항을 `main`에 동기화했습니다.

## 버그 수정
- 배포된 온라인샵 카드 결제 위젯이 반복 초기화되며 에러 문구가 깜빡이던 문제를 수정했습니다.
- `/shop/...` 체크아웃에서 로그인 필요 시 일반 이메일 로그인 대신 카카오 우선 로그인 화면으로 이동하도록 바꿨습니다.
- 모바일 `/shop/...` 결제 카드 여백을 조정해 좁은 화면에서 토스 결제수단 라벨이 눌려 보이던 문제를 완화했습니다.
- `/order/.../checkout` 두 경로에서도 토스 위젯 준비 콜백을 안정화해 카드 위젯 깜빡임이 다시 발생하지 않도록 했습니다.
- 모바일 `/shop/...` 결제 블록 폭을 표준 체크아웃 화면에 더 가깝게 넓혀, 좁은 화면에서 토스 위젯 텍스트가 넘치던 현상을 줄였습니다.
- 데스크톱 `/shop/...`에서는 주문 박스를 상품 목록 아래로 내려, 토스 결제 위젯이 좁은 사이드바 대신 넓은 폭에서 렌더되도록 바꿨습니다.
- 카드 결제 주문의 주문 완료 알림톡이 주문 생성 직후가 아니라 실제 Toss 승인 성공 시점에 발송되도록 조정했습니다.
- 운영 스키마가 일부 최신 배송 컬럼을 아직 갖고 있지 않아도 카드 결제 승인 확인이 실패하지 않도록 보완했습니다.
- 카드 승인 후 알림톡 조회나 발송이 실패해도 이미 승인된 결제가 `Failed to fetch order` 에러로 고객 화면에서 실패 처리되지 않도록 분리했습니다.
- `/payments/prepare`가 배송 전용 컬럼에 의존하지 않도록 분리해, 운영 DB에 `orders.customer_address1`, `orders.customer_address2`, `orders.fulfillment_type`가 없어도 카드 결제 준비가 실패하지 않게 했습니다.
- `/shop/...` 상단 브랜드 프로필 헤더 폭을 아래 상품/주문 카드 폭과 맞춰 데스크톱 화면에서 위쪽 박스만 과하게 넓어 보이던 문제를 정리했습니다.
